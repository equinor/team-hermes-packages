# Logging Events & Errors

Once `TelemetryProvider` is in the tree, use these hooks to log telemetry from any component.

---

## `useTelemetry()`

Returns the raw `Telemetry` object for direct calls:

```tsx
import { useTelemetry } from '@team-hermes/react-components'

function DangerButton() {
  const telemetry = useTelemetry()

  const handleClick = () => {
    telemetry.trackEvent('danger-button.clicked', { source: 'settings' })
  }

  return <button onClick={handleClick}>Do something dangerous</button>
}
```

## `useTrackEvent(name, baseProps?)`

Returns a stable callback that fires a named event. Useful when you want to attach telemetry to an event handler without referencing the telemetry object directly:

```tsx
import { useTrackEvent } from '@team-hermes/react-components'

function FilterPanel({ filterId }: { filterId: string }) {
  const trackFilter = useTrackEvent('filter.applied', { filterId })

  const handleApply = (value: string) => {
    applyFilter(value)
    trackFilter({ value })
    // logs: { filterId, value }
  }

  return <button onClick={() => handleApply('active')}>Apply</button>
}
```

`baseProps` are merged with any extra props passed at call time. The callback identity is stable across re-renders.

---

## `useTrackMount(name, props?)`

Fires an event once when the component mounts. Use for "this view was opened" or "this dialog rendered" style tracking:

```tsx
import { useTrackMount } from '@team-hermes/react-components'

function InspectionDetails({ id }: { id: string }) {
  useTrackMount('inspection-details.viewed', { id })

  return <div>...</div>
}
```

## Error tracking in event handlers

React error boundaries only catch render-phase errors. For errors in event handlers or async code, catch and report them explicitly:

```tsx
const telemetry = useTelemetry()

const handleSubmit = async () => {
  try {
    await submitForm()
  } catch (err) {
    telemetry.trackException(err, { action: 'form.submit' })
    showErrorToast()
  }
}
```

Unhandled promise rejections and uncaught errors are automatically captured by `registerGlobalErrorHandlers`, but explicit tracking gives you richer context.
