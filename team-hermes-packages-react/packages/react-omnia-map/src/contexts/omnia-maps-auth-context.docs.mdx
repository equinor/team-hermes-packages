# OmniaMapsAuthContextProvider / useOmniaMapsAuth

An opt-in companion for private web maps. `OmniaMap` never renders sign-in UI; use this provider and hook to build your own gate.

## Usage

```tsx
import { OmniaMapsAuthContextProvider, useOmniaMapsAuth } from '@team-hermes/react-omnia-map'

export function Root() {
  return (
    <OmniaMapsAuthContextProvider appId="<your app id>" portalUrl="https://omnia.maps.arcgis.com">
      <App />
    </OmniaMapsAuthContextProvider>
  )
}
```

- `appId` is the OAuth2 app ID from the ArcGIS Developer Dashboard. `appId` and `portalUrl` are read once on mount.
- `portalUrl` defaults to `https://www.arcgis.com`. For `https://omnia.maps.arcgis.com`, contact the core Omnia Maps team to allow your app domains (CORS).
- Sign-in redirects the whole page by default. Set `popup` to sign in through a popup window instead, which is required when the app runs in an iframe (such as Storybook). The popup flow needs an `oauth-callback.html` page served at the root of your app (Esri provides [a sample](https://github.com/Esri/jsapi-resources/blob/main/oauth/oauth-callback.html)), and its URL must be registered as a redirect URI on your OAuth2 application.

## Examples

The examples use the placeholder `appId` `client_id_replace_me` and the `popup` flow, because Storybook runs stories in an iframe. Signing in with the placeholder fails with “Invalid client_id”. Enter your own app ID in the controls (the provider remounts when it changes) and register this Storybook's `oauth-callback.html` as a redirect URI on that app.
